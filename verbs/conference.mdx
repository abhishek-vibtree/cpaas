---
title: "<Conference>"
description: "Put the caller into a named conference room — a persistent multi-party bridge with mute, hold, capacity, and lifecycle control."
---

`<Dial><Conference>` places the caller into a **named room**. The room is a persistent, multi-party audio bridge: any number of calls (and REST-added participants) can join it. It outlives any single member — only the last member leaving, or a member with `endConferenceOnExit`, tears it down.

```xml
<Response>
  <Dial>
    <Conference statusCallback="https://your-app.example/conf-events"
                statusCallbackEvent="start end join leave mute hold">
      support-room-42
    </Conference>
  </Dial>
</Response>
```

Call the same DID from two phones with this document and both land in `support-room-42` and hear each other.

## Attributes

<ParamField path="startConferenceOnEnter" type="boolean" default="true">
  Whether the conference **starts** when this participant joins. `false` = hold-until-moderator: the participant waits on hold (music) until a participant with `true` joins, then everyone is connected.
</ParamField>
<ParamField path="endConferenceOnExit" type="boolean" default="false">
  If `true`, the whole room ends (everyone is removed) when this participant leaves.
</ParamField>
<ParamField path="muted" type="boolean" default="false">
  Join muted (the participant's audio is not sent to the room).
</ParamField>
<ParamField path="beep" type="string" default="true">
  Play a beep into the room when this participant joins.
</ParamField>
<ParamField path="maxParticipants" type="integer" default="250">
  Reject a join once the room is full.
</ParamField>
<ParamField path="statusCallback" type="string">
  URL for room events. See [Conference events](/conference/events).
</ParamField>
<ParamField path="statusCallbackEvent" type="string">
  Space-separated subset of `start end join leave mute hold speaker announcement`.
</ParamField>
<ParamField path="record" type="string" default="do-not-record">
  `record-from-start` records the conference mixing bridge. Fires `recordingStatusCallback` and produces a downloadable recording (`RecordingSource=Conference`). See [Recordings](/api-reference/recordings).
</ParamField>
<ParamField path="recordingStatusCallback" type="string">
  URL for the recording-completion callback when `record` is set.
</ParamField>
<ParamField path="waitUrl" type="string">
  Hold audio for `startConferenceOnEnter="false"` waiters. Currently maps to a music-on-hold class (arbitrary waitUrl-TwiML is not executed).
</ParamField>

## Controlling a room

Once participants are in a room, use the [Participants REST API](/api-reference/participants) to:

- **Add** a participant (dial a phone/SIP destination into the room)
- **List** the participants
- **Mute / hold** a participant
- **Kick** a participant
- **End** the whole room

## Coaching, hold-until-moderator, recording

These are all supported — see the [Participants API](/api-reference/participants) for coaching (`Coaching` + `CallSidToCoach`) and announcements (`AnnounceUrl`), and the attributes above for recording and hold-until-moderator.

<Note>
**Coaching / whisper** uses an ARI snoop so the coach hears the room but is heard only by the coached participant. Validate on a test call before production use. **Custom `waitUrl`** audio maps to a music-on-hold class rather than running arbitrary waitUrl-TwiML.
</Note>
