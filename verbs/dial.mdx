---
title: "<Dial>"
description: "Connect the caller to another party — a phone number, a SIP peer, or a conference room — with action continuation and per-leg status callbacks."
---

`<Dial>` connects the current caller to one or more destinations. It is **not terminal**: when the dialed leg ends, OneML either fetches the `action` URL or continues to the next verb.

## Attributes

<ParamField path="action" type="string">
  URL fetched when the dial completes, with `DialCallStatus` + `DialCallDuration`. See [Action continuation](/webhooks/action-continuation).
</ParamField>
<ParamField path="timeout" type="integer" default="30">
  Seconds to ring the callee before giving up (no-answer).
</ParamField>
<ParamField path="callerId" type="string">
  Caller ID presented to the callee. Defaults to the original caller.
</ParamField>
<ParamField path="method" type="string" default="POST">
  HTTP method for the `action` request.
</ParamField>
<ParamField path="record" type="string" default="do-not-record">
  Record the connected call. Any Twilio value other than `do-not-record` enables it: `record-from-answer`, `record-from-answer-dual`, `record-from-ringing`, `record-from-ringing-dual`. Recording starts when the two legs connect. See [Recording](#recording) below.
</ParamField>
<ParamField path="recordingStatusCallback" type="string">
  URL that receives the signed recording-completion callback (`RecordingUrl`, `RecordingSid`, `RecordingDuration`).
</ParamField>
<ParamField path="recordingStatusCallbackEvent" type="string" default="completed">
  Which recording events to send. `completed` is emitted when the recording finishes.
</ParamField>

## Nouns

### `<Number>`

Dial a PSTN number. The destination is resolved through your **Routes table** (trunk + national/E.164 formatting) — see [Outbound routing](/outbound/routing).

```xml
<Response>
  <Dial timeout="25" action="https://your-app.example/after">
    <Number>+819012345678</Number>
  </Dial>
</Response>
```

### `<Sip>`

Dial a SIP destination. A URI whose host resolves to a **configured peer** (for example, an AI agent trunk such as Retell) is dialed directly. **Arbitrary SIP URIs** are also supported when a gateway endpoint is configured (`ONEML_SIP_GATEWAY`, off by default) — the full Request-URI is dialed through it, optionally restricted by a destination allowlist. Per-URI `username`/`password` digest auth is not yet supported.

```xml
<Response>
  <Dial callerId="+81345885303">
    <Sip statusCallback="https://your-app.example/status"
         statusCallbackEvent="initiated ringing answered completed">
      sip:agent@retell
    </Sip>
  </Dial>
</Response>
```

### `<Conference>`

Put the caller into a named room. See the dedicated [Conference](/verbs/conference) page.

## Per-leg status callbacks

Add `statusCallback` + `statusCallbackEvent` to a `<Number>` or `<Sip>` noun to receive `initiated` / `ringing` / `answered` / `completed` events for that leg. See [Call status callbacks](/webhooks/status-callbacks).

## Recording

Add `record` to record the connected call. Recording begins when the two legs bridge, and when the call ends OneML posts a signed callback to `recordingStatusCallback` and makes the audio available at the [recording download endpoint](/api-reference/recordings).

```xml
<Response>
  <Dial record="record-from-answer-dual"
        recordingStatusCallback="https://your-app.example/recording-status">
    <Number>+819012345678</Number>
  </Dial>
</Response>
```

The callback carries `RecordingUrl`, `RecordingSid`, `RecordingDuration`, and `RecordingStatus=completed`. Fetch `RecordingUrl` (or `RecordingUrl + ".mp3"`) with HTTP Basic auth to download the audio.

<Note>
v1 records a **mono** mix of the call (both parties combined) — suitable for transcription. The `-dual` values are accepted; true dual-channel (separate stereo tracks) is a planned refinement. See [Recordings](/api-reference/recordings).
</Note>

<Note>
**Not yet supported on `<Dial>`:** the `<Client>` noun (WebRTC browser agents) and the `<Queue>` noun are parsed but not acted on. Track these on [Compatibility](/compatibility).
</Note>
