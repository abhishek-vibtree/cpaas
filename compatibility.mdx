This page is the source of truth for **what works today** and **what is still pending**. Everything marked ✅ has been verified on live calls.

<Note>

## The big remaining items

<AccordionGroup>
  <Accordion title="#1 <Client> / WebRTC (browser agents)" icon="globe">
    The production app's human-agent dialer uses the Twilio Voice SDK — the browser originates over WebRTC. OneML has no `<Client>` / WebRTC support yet. This is the largest remaining sub-project (WSS + DTLS-SRTP + TURN + a Voice-SDK-compatible client). Required before human agents can answer/place calls in the browser.
  </Accordion>
  <Accordion title="#2 <Record> + recordings" icon="microphone">
    `<Record>`, `record` on `<Dial>`, `RecordingUrl`, `recordingStatusCallback`, recording storage, and a Twilio-compatible recording-download REST endpoint (the app's recording processor fetches recordings from the REST API).
  </Accordion>
  <Accordion title="#3 <Say> TTS and <Play> remote audio" icon="volume-high">
    A text-to-speech engine for `<Say>`, and a fetch-and-cache step so `<Play>` can play remote audio URLs. Both are parsed today but skipped.
  </Accordion>
  <Accordion title="#4 Publish the REST API" icon="cloud">
    Expose the REST API publicly (Cloudflare Tunnel) so the app can change its `api.twilio.com` base URL to OneML. Prerequisite: set the internal shared secret on both services; scope ingress to the public REST paths only.
  </Accordion>
  <Accordion title="#5 Outbound REST CreateCall" icon="phone-arrow-up-right">
    `POST /Calls.json` for standalone outbound origination (if the app needs server-initiated calls beyond Retell/Voice-SDK). The routing layer already exists; the resource does not.
  </Accordion>
</AccordionGroup>

## App-side integration notes

To point the production OneInbox app at OneML:

- Set a DID's **Voice URL** to the app's existing inbound TwiML function — OneML executes the same TwiML.
- Ensure the app validates `X-Twilio-Signature` with the **account's OneML AuthToken** (store it where the app reads it, or fetch it from `GET /Accounts/{sid}.json`).
- Two known in-app dependencies on `api.twilio.com` must be re-pointed at the OneML base when the corresponding features land: **recording download** and any **sub-account token fetch**.
